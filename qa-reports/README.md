# Multilingual QA Reports

This folder is the controlled intake and archive location for QA reports generated by Officer Command Centre.

## Workflow

1. Generate a QA report from the Multilingual Test site.
2. Upload the JSON report into `incoming/` using a unique filename, preferably `QA-YYYY-MM-DD-NNN.json`.
3. Tell the reviewer the exact filename (or commit) to inspect.
4. After review, move the report into `reviewed/`. Retain historical reports in `archive/` when appropriate.

## Report requirements

Each report should include, where available:

- A unique report ID and generation timestamp (UTC, ISO 8601).
- Application version, environment, repository/branch and commit SHA.
- Language/locale tested.
- Test names, expected and actual results, pass/fail status.
- Failure details and concise evidence (error text, relevant UI section, or reproducible steps).
- A summary count of passed, failed, skipped and not-run checks.

Keep reports self-contained and reasonably sized. Prefer recording successful checks as compact structured results and reserve detailed evidence for failures.

## Safety and release controls

- Reports are evidence only; uploading a report must never modify application code or trigger a deployment or release.
- Do not include passwords, access tokens, private account data, personal information, or other secrets.
- This directory is for Multilingual **Test** QA. Do not place production user data here.
- A report is not considered reviewed until its findings have been explicitly analysed.
